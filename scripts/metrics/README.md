# scripts/metrics

## 設計検証（docs/verification.md の根拠）

**スケールの正は `packages/tokens` にある。** ここのスクリプトは import する側であり、
値をリテラルで持たない（理由は `docs/agent-failures.md` の記録を参照）。

| ファイル | 役割 |
|---|---|
| `observed.mjs` | 既存4プロジェクトから実値を抽出する |
| `generate-scales.mjs` | スケールを表示する。**人が目で見るためのもので、検査ではない** |
| `verify-coverage.mjs` | 実測値に対するスケールのカバー率を計算する |
| `pr-metrics.mjs` | **開発プロセスを計測する。** PR・Issue・workflow run から集計する |

```bash
pnpm scales            # スケールを表示する
pnpm verify:coverage   # 実需要に対するカバー率を出す
pnpm metrics           # 開発プロセスを計測する（gh とネットワークが要る）
```

## 開発プロセスの計測（development-process.md の「計測」）

**このリポジトリは AI 駆動開発の実践例を兼ねている**（CLAUDE.md）。
`pr-metrics.mjs` は GitHub API だけを出典に、5つの指標を出す。

**値をファイルに残さない。** API が履歴そのものなので、走らせ直せば同じ数が出る。
生成物をコミットしない（原則1）のと同じ扱いにする。

| 指標 | 取り方 | 取れないもの |
|---|---|---|
| リードタイム | `Closes #N` で Issue を引き、作成 → マージ | Issue を持たない PR は「—」 |
| 自己レビューの回数 | `pr.reviews` の件数 | 中身の質 |
| **初回コミットが CI を通った割合** | 初回コミットの sha と**ブランチ名**で run を引く | 同じコミットに複数の PR がぶら下がる場合は**判定不能として出す** |
| CI 失敗の原因 | **落ちた step の名前**をそのまま分類に使う | 保持期間を過ぎたジョブは「不明」 |
| 人手の介入 | `Co-Authored-By: Claude` を持たないコミット | **理由は取れない** |

**「落ちた」と「動かなかった」を混ぜない。** run が作られない・`queued` のまま固まる
ことが実際にあった（2026-08-26 の Actions 障害）。`CI 導入前` と `未実行` を
独立した区分として出し、**割合の母数から外す。**

**「0 件」を成功として出さない**（教訓2）。CI 失敗が 0 件のときは、履歴の中から
落ちた run を1つ拾って分類器を当て、**発火することを確かめてから**0 件と言う。

**最重要指標が測っていないことを、数の隣に出す。** 「初回コミットが CI を通った割合」が
測っているのは**push 前に検査を走らせているか**であって、正しいコードを書けるかではない。
CI が走らせるのは手元と同じ検査なので、緑にしてから push すれば通るのは半ば同語反復である。

**判定は script が下さない。** 自己レビュー 0 回の PR は並べるだけにする。
実装でない PR もあり、違反かどうかは読む人が決める。

**不変条件の検査は `packages/tokens/test/scales.test.ts` が担当する（`pnpm test`）。**
`docs/decisions.md` に記載した値との一致もそこで検証している。

スケールの規則を変更したら `pnpm verify:coverage` を再実行し、
`docs/verification.md` の数値を更新すること。**これは CI では動かない**（下記）。

### 前提

`observed.mjs` は `~/ghq/github.com/shun2218-dev/` 配下に
ichirizuka / pylabo / holosphere / pdf-merge-app が存在することを前提としている。
**CI では動かない。** 見つからない場合は該当パスを報告して終了する。

## 開発プロセスの計測（Phase 1 で実装）

PR メタデータから以下を収集する。

- Issue 作成からマージまでのリードタイム
- PR あたりの自己レビューイテレーション回数
- **エージェントの初回コミットが CI を通った割合**（最重要指標）
- CI 失敗の原因分類（型 / テスト / lint / トークン規約違反 / 視覚回帰）
- 人間が介入した回数と理由
