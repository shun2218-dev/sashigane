# 実験: 面の帯の配分と、字送りの係数

実施日: 2026-09-13
対象: Chromium（Claude Code の Browser ペイン）で各サイトの計算値を読む / 生成器の出力
関連: [decisions.md 決定5-2・1-8・1-9・5-16](../decisions.md) / [Issue #265](https://github.com/shun2218-dev/sashigane/issues/265)

## なぜ実験したか

「見た目が古い」という申告に対して、**どこが古いのかを推測で決めない**ため。
`getComputedStyle` を使えば、どのサイトも実際に置いている値が読める。
訓練データの記憶や解説記事ではなく、**動いている実装の計算値**を出典にする。

## 測り方

各サイトを開き、次を読んだ。

- ボタンらしき要素（`button` / `a[class*=utton]` / `[role=button]`、高さ 24〜80px）の
  `border-radius` / 高さ / `font-size` / `font-weight` / `box-shadow`
- `h1` / `h2` の `font-size` / `font-weight` / `letter-spacing`
- ページ全体の `border-radius` と `box-shadow` の集合
- 中間色ランプは、`--color-neutral-*` を空の要素に当てて計算値を読み、Lab の L\* に直した

**マーケティングのページを測っている。** アプリ本体の画面ではないので、
ボタンの寸法はアプリより大きめに出ている可能性がある——
shadcn/ui（32〜36px）と GitHub（32px）が小さいのは、文書サイトの中の実物を拾っているためである。
**角丸・太さ・字送り・影の作りは、この偏りの影響を受けにくい。**

## 中間色ランプの L\*

```
Tailwind neutral  98.3  96.5  91.0  84.9 │ 66.1  48.5  34.9  27.0  15.2   7.8   2.8
sashigane（前）   96.5  86.4  76.2  66.1 │ 55.9  45.8  37.8  29.7  21.7  13.6   5.8
sashigane（後）   98.9  93.7  84.4  72.4 │ 57.7  47.4  39.7  31.9  24.2  16.5   8.8
                  └── 面の梯子 ──┘
```

**3段目が問題だった。** L\*66 は Tailwind の neutral-400 と同じ濃さで、背景に使う値ではない。

Radix Colors は12段のうち 1〜2 を背景、3〜5 を部品の背景に割いている（計5段）。

**ここで測った範囲を書いておく。** ランプの値を数値で読んだのは **Tailwind の1本だけ**である。
Radix は文書の役割配分を読んだだけで、値は測っていない。**残り5本のランプは測っていない。**
言えるのは「Tailwind と Radix は明色端を細かく刻んでいる」までで、
「等間隔の実装は無い」ではない（教訓2・5）。

## 曲率の上限をどう決めたか

`backgroundCurve` を上げるほど段100 が上端へ寄る。**寄りすぎると3つが同時に痩せる。**

| `backgroundCurve` | L\*(50/100/200/300) | 帯の最小段（>1.1） | 淡い塗りの彩度（>0.02） | 影の対比 |
|---|---|---|---|---|
| 1 | 98.9 / 88.6 / 78.3 / 68.0 | 1.278 | 0.0570 | 1.27〜1.31 |
| **1.5** | **98.9 / 93.7 / 84.4 / 72.4** | **1.128** | **0.0257** | **1.13〜1.14** |
| 1.75 | 98.9 / 95.2 / 86.7 / 74.2 | 1.088 ✗ | 0.0195 ✗ | 1.09〜1.10 |
| 2 | 98.9 / 96.3 / 88.6 / 75.9 | 1.061 ✗ | 0.0151 ✗ | 1.06〜1.07 |

彩度は全360色相の最小を取っている。**1.5 が3つとも保ったまま取れる最大である。**

## 先に試して壊した形

**アンカー段まで曲げる形を先に書いた。** 段400 が明るくなってページ地に対する 3:1 を割り、
償うためにアンカーが暗くなる。アンカーは暗色側でも段500 なので、下端が押し下げられた。

| | アンカー | 下端 | 暗色のページ地 L\* |
|---|---|---|---|
| アンカーまで曲げる（curve=2） | 0.450 | **0.020（探索の床）** | **0.0** |
| 保証の段で止める（curve=1.5） | 0.546 | 0.214 | 8.8 |

**保証の表に出てくる段（400・500）を直線の上に残す**と、端点の解が1つも動かない。
`backgroundCurve = 1` を入れると改訂前と完全に一致する。

## 上端を 0.99 より上げられない理由

上端を上げるほど、段100 で取れる彩度の上限が下がる。
`top = 0.99` かつ `backgroundCurve = 1.75` の組で、**`#ffff00` が
「sRGB で再現できない」の警告を出さなくなった。**

警告が出るべき入力で出ないのは、検査が緩んだということである（教訓2）。
**0.99 × 1.5 では両方の警告が期待どおりに出る**（`#ffff00` は出て、`#e879f9` は出ない）。

## 字送りの係数

見出しの実測から `coefficient = 実測 ÷ (root/size − 1)` で逆算した。

| 出典 | サイズ | 実測 | 逆算した係数 |
|---|---|---|---|
| Vercel | 48px | −0.060em | 0.090 |
| Notion | 42px | −0.036em | 0.058 |
| shadcn/ui | 30px | −0.025em | 0.054 |
| Linear | 38px | −0.022em | 0.038 |
| Stripe | 34px | −0.010em | 0.017 |

中央値 0.054 → **0.05 を採った。**

**GitHub と Mantine の 0 は母数に入れていない。** 0 は「詰めない」という別の選択であって、
小さい係数ではない。混ぜると「詰めるが弱い」に見えるが、実際には詰めない実装が2つあるだけである。

## この実験が答えていないこと

- **測ったのはマーケティングのページである。** アプリ本体の画面は測っていない
- **ランプの値を数値で読んだのは Tailwind の1本だけである。** 残り5本は測っていない
- **書体を測っていない。** 7本中6本が独自の書体を持っており、
  見た目の差のうちどれだけが書体由来かは、この測り方では分けられない。
  sashigane は書体の値を持たない（決定1-11）ので、この軸は利用側に残る
- **角丸・太さ・影の使用はコンポーネント層の話である。** ここでは測っただけで、直していない
