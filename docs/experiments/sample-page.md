# 実験: 生成した変数だけでページが組めるか

実施日: 2026-08-27
関連: [Issue #61](https://github.com/shun2218-dev/sashigane/issues/61) / 原則3・原則4・原則7

## なぜ確かめたか

テーマビルダーは色を見せていたが、**それが実際に組めるかは見せていなかった。**

`Preview` は JS で計算した色を `style` 属性へ直接入れており、通っていたのは色だけである。
`--sg-space-*` も `--sg-text-*` も `--sg-radius-*` も1つも経由していない。
`public/standalone.html` はトークン層が単体で成立することを見せているが、
あちらは**ビルド時の固定パレット**で、選んだ色とは連動しない。

そこで「生成した CSS 1枚だけを読み込んだ LP」を書き、
**セマンティックだけでどこまで組めるか**を確かめた。

## 方法

`apps/docs/src/sample-page.html` を素の HTML で書き、iframe に読み込む。
テーマビルダーが `toTokensCss(palette)` の結果を `<style id="sg-tokens">` へ流し込む。
**iframe の中に入るのはこの CSS だけで、React もビルダーの style.css も届かない。**

`data-theme` / `data-sg-density` / 幅 / 書体の差し込み口はビルダー側の操作で切り替える。
数え上げと生値の検査は `pnpm check:sample-page` が行う（陰性対照つき）。

## 結果

### セマンティックは 64 個すべてが使えた

色 34・タイポグラフィ 27・骨格の余白 3 の全部に**置き場所があった。**
「役割はあるが使い道が思いつかない」名前は1つも無かった。

用途が見つけにくいのではと思っていた `--sg-color-sequential-*`（連続値の帯）と
`--sg-text-body-prose-*`（読ませる長文の行高）にも、LP の中に自然な置き場所があった。

### セマンティックが無い次元は、避けられなかった

| 次元 | 踏んだ回数 | 主な用途 |
|---|---:|---|
| `space`（段） | 64 | コンポーネント内部の `gap` `padding` `margin`、アイコンの一辺 |
| `radius` | 14 | ボタン・カード・入力欄の角 |
| `border-width` | 12 | 枠線、輪郭、通知の左端 |
| `radius-full` | 4 | 円形の点、丸いバッジ |
| `duration` | 3 | ホバーと枠線色の遷移 |
| `duration-loop` | 1 | 稼働中を示す点の明滅 |

**骨格の余白（`page` / `section` / `surface`）は3つとも足りていた。**
不足しているのは**コンポーネント内部の余白**で、決定1-12 が
「密度で動くのは骨格だけ」と切り分けたとおりの分布になっている。
段の内訳は 3（17回）・4（14回）・5（10回）・2（10回）に集中する。
**段0 は1度も使わず、段8・9 は各1〜2回**で、使われるのは中央の数段だけだった。

`space` の 64 回のうち9回は `width` / `height` である。
アイコンや点の**一辺**を spacing の段で書いた。**寸法のスケールが無い**ためで、
これは余白とは別の需要である可能性がある。

### 使えなかったもの

- **`--sg-elevation-*`** — 値が高さの数値しか無く、影の仕様が未定のため（決定1-8）。
  LP に影を1つも置いていないのはそのためで、意図的に**それらしい影を書かなかった。**
  書けば決定していない仕様を既成事実にしてしまう
- **`--sg-breakpoint-*`** — メディアクエリの中では CSS 変数が使えない（決定1-10）。
  素の CSS の利用者は値を直接書くことになる。LP も `48rem` と書いている

### そもそも次元が無いもの

上の2つは「あるが使えなかった」もので、**無いものは別にある。**

```css
.btn:hover { opacity: 0.88; }      /* 不透明度 */
.label { letter-spacing: 0.08em; } /* 字送り */
.hero .lead { max-width: 46ch; }   /* 行長 */
```

この3つはスケールを**持つべきかどうかすら決めていない。**
LP は生値で書いており、`check:sample-page` は色を持ちうるプロパティしか見ないので
**発火しない。** 見逃す範囲としてスクリプト冒頭にも書いた（教訓5）。

**字送りは既に Issue になっている。**
[#46](https://github.com/shun2218-dev/sashigane/issues/46) が「決定1-9 の係数が確定していない」として保留にしており、
LP でも `.label`（eyebrow）で実際に必要になった。**保留中の決定が実需要に当たった1件目である。**

不透明度は Issue も決定も無い。「無効状態」「重ね幕」で必ず要求される次元なので、
**次に観測するときの候補になる。**

### 借りたもの

塗りの上の文字色に `--sg-color-bg-page` を使った。
**on-accent の役割が無い**ためで、[Issue #59](https://github.com/shun2218-dev/sashigane/issues/59) に記録済みの穴が、
LP を組むと**必ず踏む場所**であることが確かめられた。

## 分かったこと

1. **色とタイポグラフィのセマンティックは、実ページを1枚組むのに過不足が無い。**
   足りない名前も、余っている名前も無かった
2. **不足しているのは色ではなく寸法である。** 内部余白・角丸・枠線幅の3つは、
   どのコンポーネントでも踏む。特に `space` は延べ 64 回で他を圧倒する
3. **影は書けない。** 決定1-8 が保留のままなので、LP に置ける影が無い
4. **次元そのものが無いものがある。** 不透明度・字送り・行長は生値で書くしかなかった

## 次に決めること

原則7 に従い、**ここでは名前を決めない。**
上の観測を根拠に、次のことを別 Issue で判断する。

- コンポーネント内部の余白に役割名を与えるか。与えるなら、密度で動かさないことを明示する
- `radius` / `border-width` のセマンティック（`--sg-radius-control` など）
- 寸法（アイコンの一辺）が spacing とは別のスケールを要求しているか
- 決定1-8（影）を解くかどうか
- 不透明度にスケールを与えるか（次元そのものが無い）。
  字送りは [#46](https://github.com/shun2218-dev/sashigane/issues/46) で保留中の決定1-9 がそのまま当たる

**このページは今後も検査対象外のフィクスチャのまま置く。**
セマンティックが増えたら書き換え、`pnpm check:sample-page` の数字が減ることで
「役割が増えてプリミティブを踏まなくなった」ことが観測できる。
