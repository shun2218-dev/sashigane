# 動かせない設計原則

対話で確定した、覆さない前提。**根拠と個別の決定は [decisions.md](./decisions.md)。**

## 1. トークンが唯一の正

`tokens.json` を単一のソースとし、CSS 変数・TS 型・Tailwind アダプタを生成する。

- 生値（`#3b82f6`、`16px`）をコンポーネントに直接書かない
- **生成物はコミットしない**

## 2. 値は導出する。既存プロジェクトから抽出しない

唯一の根本定数は `root = 16px`。基準と比率を決め、そこから機械的に生成する。

過去の実装は「需要の観測」には使うが「値のソース」には使わない。
既存4本を平均しても一貫性は生まれない。

`root` から導けない次元は例外として明示する。現在2つある。

- **時間（duration）** — 独自のアンカー（200ms / 1000ms）を持つ（決定1-6）
- **書体（font-family）** — 値を持たない。スタックの構造だけを規定し、
  書体名は利用側が差す（決定1-11）。書体名はブランドの選択であってシステムの選択ではない

## 3. プリミティブ層とセマンティック層を分ける

| 層 | 形 | 参照 |
|---|---|---|
| プリミティブ | `--sg-{category}-{数字}` | **禁止** |
| セマンティック | `--sg-{category}-{単語}` | 可 |

プリミティブは生成物なので全段用意してよい。
セマンティックは**実際に使う場所が1つ以上あるものだけ**定義する。

名前が数字で終わるか単語で終わるかで層が判別できるため、lint は1つの正規表現で強制できる。

## 4. 依存は一方通行

`packages/tokens` は React も `packages/ui` も import しない。

CI が検査している（`pnpm check:tokens-isolation`）。
「react を禁止する」ではなく「相対パスと `node:` 以外を全部禁止する」形で実装している。

**トークン層が単体で成立することが、この設計の証明になる。**

## 5. 色は OKLCH で生成する

明度ステップを揃えることで、任意の色相の組み合わせでコントラスト比が構造的に保証される状態にする。

**WCAG 適合を「後から検査して直すもの」ではなく「そうなっているもの」にする。**

保証の対象は**面の段ごと**である。面が深くなると役割が参照する段も深くなる（決定5-12）。
面は `data-sg-surface` で宣言する。**塗るだけの方法は用意しない。**
塗れてしまうと前景がページ用のまま残り、保証が崩れてもエラーにならない。

## 6. 配布は shadcn レジストリ方式

npm パッケージではなく、利用側リポジトリにコードを落とす。3段階の導入深度を成立させる。

| 深度 | 内容 |
|---|---|
| `@sashigane/tokens` | CSS 変数のみ。React 非依存 |
| `@sashigane/<component>` | コンポーネント単体 |
| `@sashigane/base` | 全部（`registry:base`） |

**トークンのみのインストールが実際に動くことが、層分離の証明になる。**

## 7. コンポーネントは実需要のあるものだけ

既存4本で3回以上書き直したものから始める。最初は5個以内。
**「あった方が良さそう」で追加しない。**

観測結果は [roles.md](./roles.md)。
なお pdf-merge-app は shadcn を58個インストールして実際に使っていたのは12個だった。

## ガードレールを足すときの順序

**必ず [agent-failures.md](./agent-failures.md) に理由を書いてから追加する。**

ルールが先にあってはならない。失敗が先にあり、ルールはその対処として生まれる。
理由の書かれていないルールは、後から誰も消せなくなる。

**消すときも同じ。** なぜ不要になったかを記録してから消す。
