既存4プロジェクトから **役割** を観測した記録。**値は取っていない**（原則2）。
「どんな役割が必要だったか」だけを拾い、値は [decisions.md](./decisions.md) の規則から生成する。

観測日: 2026-08-23

| 記号 | プロジェクト | 性格 |
|---|---|---|
| **i** | ichirizuka | 明色・フラット（影と角丸を使わない）・データ密度が高い |
| **p** | pylabo | 暗色優先＋明色テーマ・長文読解・コード実行 |
| **h** | holosphere | 暗色のみ・アルファ合成で面を作る・チャートが多い |
| **s** | pdf-merge-app | shadcn 既定値。**本人の選択ではないため需要の証拠としては弱い** |

hozo-ui は観測対象に含めていない。

## 面（surface）

| 役割 | 観測 | 備考 |
|---|---|---|
| `bg-page` | i p h s | |
| `bg-surface` | i p h s | カード・パネル |
| `bg-surface-subtle` | p | ページとカードの中間。**退けた**（決定5-13）。明色の 50 と 100 の間に段が無く、足すと `bg-hover` と両立しない |
| `bg-inset` | i p s | **凹んだ面**。入力欄、進捗トラック、コードブロック地 |
| `bg-overlay` | h s | **不透明でなければならない**（下記）。`data-sg-surface="overlay"`（決定5-13） |
| `bg-hover` | i p h | `data-sg-interactive` で作る面の文脈（決定5-13） |
| `bg-active` | i p h | **保留。** 2段深い面は梯子に無い（決定5-13） |
| `bg-decorative-grid` | i | 方眼の描画線。罫線とは別の値を持っている |

**面はすべて不透明なので、下の制約は sashigane では既に満たされている。**
overlay に残っているのは「浮いて見える」ことだけで、それは elevation（決定1-8、未実装）の責務である。

### アルファ面は重なりに使えない

holosphere は面を `bg-white/[0.03]`、境界を `border-white/10` とアルファで組み立てているが、
ツールチップだけは `bg-[#13131f]` と不透明の生値を使っている。
アルファ面は下地が透けるため、重なる要素には使えない。

**`bg-surface` と `bg-overlay` は「同じ色の別の段」ではなく、構成方法からして別の役割である。**

## 境界（border）— 4段階の濃さが必要

| 役割 | 観測 |
|---|---|
| `border-subtle` | i（表の行区切り） p |
| `border-default` | i p h s |
| `border-strong` | p（hover 時、accent を混ぜる） |
| `chart-gridline` | h — **UI の境界よりさらに薄い** |

4段とも決定5-13 でトークンになった。面と一緒に深い側へずれる。
観測された「hover 時に濃くなる」は面の文脈が担うので、`border-strong` は
**hover ではない強調**（選択中の行、強調した区切り）のために残している。

チャートのグリッド線が UI の境界より薄いのは意図的で、データを邪魔しないため。
`border-subtle` で代用できない第4の段が存在する。

## 文字（text）— こちらも4段階

| 役割 | 観測 |
|---|---|
| `text-default` | i p h s |
| `text-muted` | i p h s |
| `text-faint` | i p |
| `chart-tick` | h — muted と faint の間 |
| `text-on-accent` | p（`#fff` をハードコード） h（`text-white`） s（`*-foreground`） |
| `text-link` | i p |
| `text-disabled` | i（色を faint に）/ p（`opacity: 0.45`）→ **不統一** |

3プロジェクトが独立に文字を3段に落ち着かせているのは強い一致。

`text-on-accent` は決定5-14 で `--sg-color-on-accent` として持った。
状態色の塗りも同じ形で持つ（`on-danger` など）。

**「明るい塗り＋暗い文字」は4本に1件も無い**（2026-08-27 に全ファイルを読み直した）。
Issue #59 が想定した組み方は観測されなかった。代わりに **p と h で最も多いのは
「淡い塗り＋アクセント色の文字」**（`color-mix(accent 7〜35%)`、`bg-*-300/15`）で、
これはどちらもアルファ合成である。決定5-14 で別の決定として切り分けた。

## 状態色（status）

| | accent | success | warning | danger | info |
|---|---|---|---|---|---|
| i | teal | **teal（兼用）** | amber | magenta | なし |
| p | 独立 | 独立 | 独立 | 独立 | なし |
| h | fuchsia | emerald | amber | rose | sky |
| s | primary | — | — | destructive | — |

### ichirizuka の accent は5つの役割を1つの値で兼ねていた

アクセント / リンク / フォーカスリング / 増加方向（delta-up） / データ塗り。

**これは値の不統一ではなく、役割の定義が存在しなかったケース。**
新システムでは5つを独立した役割として定義する。

### status は3つの変種を持つ

pylabo と holosphere が独立に同じ構成に到達している。

| 変種 | 用途 |
|---|---|
| 前景色 | アイコン・文字 |
| 淡い背景（元色の 12〜15%） | 帯・バッジの地 |
| 境界（元色と border-default の 45% 混合） | 枠線 |

---

## 識別色（categorical）— status と衝突してはならない

pylabo にこの制約が明示的に書かれている。

> アクセント色はコースの識別色で、難易度の手がかりにはならない
> 赤系は採点の失敗色（--err）と紛れるため、実践は紫にしている

**識別色は「余った色」ではなく、status 色との衝突を避けるという制約を持った独立した役割。**
OKLCH で色相を等間隔に配る際、status が占める色相帯を除外する必要がある。

|---|---|
| `chart-series-1..N` | i（3系列） h（4系列） s（5系列） → **N = 5 が安全圏** |
| `chart-gridline` | h |
| `chart-axis` | h |
| `chart-tick` | h |
| `chart-crosshair` | h |
| `chart-selection` | h（ブラシ選択範囲。stroke と fill で別値） |

## 密度（density）— 当初認識していなかった軸

ichirizuka はセクション間隔をブレークポイントで切り替えている。

```
:root          --gap: 28px
@media(≤780px) --gap: 22px
```

これは「レスポンシブな余白」ではなく**密度という独立した軸**の現れ。
同じセマンティック役割が、文脈によって別のプリミティブ段を指す。

> **2026-08-26 追記。** 2件目を holosphere で観測し、決定1-12 として実装した。
> **密度で動くのは骨格の3箇所だけ**である（ページの左右 / セクション間 / 面の内側）。
> holosphere の余白 572 箇所のうち、ブレークポイントで動くのは 26 箇所（約 4.5%）だった。
>
> | | 密度をどこが持っているか |
> |---|---|
> | ichirizuka（コンポーネント無し） | CSS 変数 `--gap` |
> | holosphere（コンポーネント有り） | `PageContainer` と `Card` |
>
> **同じ需要が、そのプロジェクトが持っている層で表現されていた。**

## コンポーネントの実需要（Phase 3 の材料）

原則7「既存4本で3回以上書き直したもの」の集計。

| コンポーネント | i | p | h | s | 回数 |
|---|---|---|---|---|---|
| **Button** | ✓ | ✓（3 variant + icon） | ✓ | ✓（12 import） | **4** |
| **Card / パネル** | ✓（5種の派生） | ✓ | ✓（3種） | ✓ | **4** |
| **Badge / Chip / Tag** | ✓ | ✓（2種） | ✓（2種） | — | **3** |
| **Table** | ✓ | ✓ | ✓ | — | **3** |
| **Separator** | ✓ | ✓ | — | ✓（4 import） | **3** |
| **進捗バー** | ✓（2種） | ✓ | ✓ | — | **3** |
| 空・エラー状態 | ✓ | ✓ | — | — | 2 |
| 折りたたみ | ✓ | ✓ | — | — | 2 |

**3回以上は6つ。最初は5個以内という制約に対して1つ多い。**
Phase 3 で優先順位を決める。

### 記録: コンポーネント欠如の症状

```css
.section-note { margin: -12px 0 18px; }   /* 見出しの下余白を打ち消している */
```

負の margin はトークンの問題ではなく、
**「見出し＋注記」がコンポーネント化されていないことの症状**。
トークンに負値を足すのではなく、コンポーネント候補として記録する。

### 記録: 導入しても使わない

pdf-merge-app は shadcn を **58個インストールして実際に import しているのは12個**だった。
原則7「あった方が良さそうで追加しない」の正しさを裏づける観測。
