## 素の dialog に乗っています

`showModal()` を呼ぶと、ブラウザが次の全部を持ってくれます。

- 最前面の層に出る（`z-index` も `overflow` も関係しない）
- **フォーカスが中に閉じ込められる**
- 後ろが操作できなくなる
- `Escape` で閉じる
- **閉じたとき、開く前にフォーカスがあった場所へ戻る**

自前で書くと、この5つを全部持ち直すことになります。

**属性だけで出すと、この層に入りません。** 入らないとフォーカスの閉じ込めも後ろの遮断も
効きませんが、**見た目は出る**ので気づけません。テストが `:modal` で測っています。

## 開け閉ては利用側が持ちます

```tsx
const modal = useModal();

<Button onClick={modal.show}>消す</Button>
<Modal open={modal.open} onClose={modal.hide} title="確認">
  本当に消しますか
</Modal>
```

開いているかどうかは**利用側が知りたい値**です——開いている間だけ読み込む、
閉じたら次の案内を出す、など。部品の中に隠すと「開いた」ことしか分かりません。

`Escape` で閉じたときも `onClose` が呼ばれます。**返さないと、
利用側は開いていると思ったまま**になり、次に押しても開きません。

## 後ろの巻き取りは自分で止めています

`showModal()` は後ろの**操作**は止めますが、**巻き取り（スクロール）は止めません。**
止めないと、中を読んでいるつもりで後ろが動きます。

## 覆いを押して閉じるのは既定ではありません

`dialog` は覆いの部分も自分の領域なので、**押した場所が中か外かを座標で見分ける**
ことになります。取り違えると、中を押したのに閉じます。
消える操作の前では代償が大きいので、`closeOnBackdrop` を渡したときだけにしています。

## 出入りに動きが付いています

ダイアログと覆いが一緒に薄れて出入りします。

**閉じるときが難しいところです。** 閉じる操作は表示を即座に消すので、
何もしないと**消えてから動く**ことになり、動きが見えません。
`display` と `overlay` を `allow-discrete` で遷移させて、
**動き終わるまで最前面の層に留まる**ようにしています。

**動きを減らす設定では動きません。** 尊重するのは利用側の責務ではないので、
トークン層で止めています。

## 幅は決めていません

**このシステムには幅の段がありません。** 素の `dialog` は中身に合わせて広がり、
画面幅で止まります。幅を決めたいときは `className` か `style` で渡してください。
