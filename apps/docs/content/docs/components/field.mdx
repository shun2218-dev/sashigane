## 結びつけを書かせません

札と入力、説明と入力、誤りと入力。**どれも忘れると読み上げだけが黙ります。**
見た目は正常なので、書き忘れても気づけません。

観測した4本でも、`htmlFor` による結びつけは**合わせて3件**しかありませんでした。

```tsx
<Field id="mail" label="メールアドレス" description="仕事用のもの" error={errors.mail} required>
  <Input type="email" />
</Field>
```

**利用側が渡すのは `id` を1つだけ**です。説明と誤りの `id` はそこから導きます。

## `id` は必須です

自動で作る道は取っていません。安定した名前を作るには `useId` が要り、
**この部品がクライアント側になる**ためです。

必須にしたことで、**書き忘れが型で止まります。**

## バリデーションは持ちません

**規則を走らせる仕組みはありません。** 誤りの文言を受け取るだけです。

受け取るのは標準の props だけなので、**どのライブラリとも組めます**——
react-hook-form でも TanStack Form でも Conform でも、素の `FormData` でも同じです。

```tsx
{/* react-hook-form の例 */}
<Field id="mail" label="メール" error={formState.errors.mail?.message}>
  <Input {...register('mail')} />
</Field>
```

### 実際に動かせます

下は **react-hook-form で検証が走る本物のフォーム**です。
打っている最中に検証が走ります——形が整うと線が緑に変わり、印が出ます。

<FormDemo />

**このリポジトリは `react-hook-form` に依存していません。** この展示だけが依存しています——
`packages/ui` の側は標準の props しか受け取りません。

組み合わせが壊れていないことは**テストが実ブラウザで測っています**（`register` を撒いても
配線が消えないこと、検証に落ちると誤りが結びつくこと、通ると値が届くこと）。

### 入力の側で配線を書くと落ちます

`id` / `aria-describedby` / `aria-invalid` は **Field が渡します。**
入力の側で書くと**こちらが渡したものが消え、結びつきだけが切れます**——
見た目は正常なままなので気づけません。だから**投げます。**

`register()` が返す `name` / `onChange` / `onBlur` / `ref` は重なりません。

## 満たしていることも表せます

```tsx
<Field id="mail" label="メール" valid>
  <Input />
</Field>
```

境界が変わり、**入力の右端に印**が出ます。印は読み上げから隠れています——
出しても「チェック」としか言わないので、**状態は境界が伝えます。**

誤りと同時には使えません。**両方は成り立たない**ので、誤りが勝ちます。

## 空の段落は置きません

説明も誤りも無いときは、**何も描きません。** 置くと、
何も書かれていない行が読み上げに出ます。

## 必須は記号だけで伝えません

`*` は読み上げに届かないので、**文字も一緒に置いています。**
