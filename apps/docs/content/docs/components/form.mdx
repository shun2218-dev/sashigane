## バリデーションは持ちません

規則を走らせる仕組みはありません。**走らせるのは利用側**です。
ここが持つのは、**利用側が書き忘れるもの**だけです。

## 送信に失敗したら、最初の誤りへフォーカスが移ります

長いフォームでは、**誤りが画面の外にあると何が起きたのか分かりません。**
送信ボタンを押しても、何も起きていないように見えます。

誤りを名乗っている欄（`aria-invalid`）を探すので、
**どのライブラリで検証したかに依りません。**

移す先は**全体の誤り → 最初の誤りの欄**の順です。全体の誤りは
「なぜ送れなかったか」を説明していて、フォームの上端にあります。
そこへ移せば、下へ読み進める形になります。

### 検証が非同期なら、約束を返してください

いつ誤りが付くかは、送信処理が終わるまで分かりません。
**約束（Promise）を返せば、その解決を待ちます**——`async` で書けばそうなります。

```tsx
<Form onSubmit={async (event) => {
  event.preventDefault();
  await validate();   // 約束を返すので、待てます
}}>
```

返さずに非同期の検証を始めた場合、**フォーカスは移りません。**
待ち続ける形にはしていません——いつやめるかを決められず、
**時間が経ってからフォーカスを奪うのは、移さないより悪い**からです。
そのころ利用者は別の場所を触っています。

フォーカスを持てないものが名乗っていることもあります（ラジオのグループは `fieldset` が名乗り、
`fieldset` にフォーカスは乗りません）。**そのときは中の最初の入力へ移します。**

動かしたくないときは `focusOnError={false}` を渡してください。

## ブラウザ既定の検証は切ってあります

既定の吹き出しは Field が出す文言と**二重になり**、見た目も位置も揃いません。
片方は読み上げに届きません。

**塞いではいません。** `noValidate={false}` と書けば素の検証に戻ります。
`required` 自体は残るので、**読み上げには届きます。**

## フォーム全体の誤り

欄1つの誤りではないもの——送信そのものが失敗したときや、
複数の欄の組み合わせが成り立たないときに使います。

**指す先がありません。** どの欄が悪いとも言えないので `aria-describedby` では結べず、
その場で読み上げに届く形（`role="alert"`）で出しています。
