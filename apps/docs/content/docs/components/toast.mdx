## どこからでも出せます

置き場は **React の外**にあります。深いところからでも、React の外
（読み込みの失敗処理など）からでも、`showToast()` をそのまま呼べます。

```tsx
showToast({ message: '保存しました', tone: 'success' });
```

文脈（context）で配っていません。配ると、**出す場所すべてが提供者の下に
いなければならず**、React の外からは出せなくなります。

読む側は `useToast()` です。出すだけなら関数で足ります。

`<Toaster />` を**アプリに1つだけ**置いてください。

## 読み上げの領域は、文言より先に描かれています

1つも出ていないときも領域だけは描いています。**後から領域ごと現れると、
読み上げは中身の追加に気づきません。**

見た目には何も出ない誤りなので、テストが測っています。

## 急を要するものはトーストで出さないでください

領域は1つで、`polite` です。重みごとに分けると、**重い方が上・軽い方が下**と
並び順が重みで決まってしまい、出た順に読めなくなります。

割り込んで伝えたいものは、トーストではなく**モーダル**で出してください。

## 既定は滞在の段のまん中です

何も渡さなければ **4秒**で消えます。値は**滞在の段**から来ています——
部品に数値は埋めていません。

**3秒を下回ると読み切れません。** 長い文言や、読んでから操作するものは
段の上の方（5.7秒・8秒）を渡してください。10秒を超えると、
気づかないまま消えたのか出ていないのかが分からなくなります。

読み終わるまで残したいものは `duration: null` を渡してください。

**ポインタが乗っている間は消しません。** 離れたらもう一度はじめから数えます——
残り時間を持つと時計が2箇所に増えるためで、**長く出る側へ倒れます。**

トークンを入れていない配布先では段が読めません。そのときは**消さない側へ倒れます**
——適当な数値を埋めると、段の外の値が1つ増えます。

## 2つ置いても描くのは1つです

`<Toaster />` は**アプリに1つ**ですが、2つ置かれても描くのは先に置いた方だけです。

2つとも描くと、重なって見えるだけでなく**読み上げの領域が2つになり、
同じ文言が2回読まれます。** 先に置いたものが外れたら、次のものへ番が渡ります。

## 最前面の層に出ます

`overflow` を持つ祖先があっても切り取られません。枠は何も塗らず押せないので、
**後ろのページはそのまま押せます。**

## 消えるときは動きません

出るときは薄れて現れますが、**消えるときはその場で消えます。**

動かすには、消す前に「消えかけ」を作り、CSS と同じ長さだけ待ってから外すことになります。
**同じ長さが CSS と JS の2箇所に要る**ので、揃っているかを誰も見られません。
モーダルは待つ側をブラウザが持っていました（`allow-discrete`）が、ここにはありません。

## 残り時間が見えます

トーストの下に帯が出て、**満ちた状態から空へまっすぐ減ります。**
加減速は付けていません——**時間そのものを表しているので、速さが変わると嘘になります。**

ポインタを乗せているあいだは止まります。**外すと、止めた続きから数え直します。**

`duration: null` を渡したものには出ません。**消えないものに残り時間はありません。**

**動きを減らす設定でも止まりません。** これは飾りではなく、
あと何秒で消えるかという情報です。止めると読み取れなくなります。

読み上げには出しません。**時間の経過を読ませると、文言が繰り返し流れます。**
