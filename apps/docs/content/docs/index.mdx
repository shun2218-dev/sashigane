`tokens.json` を単一のソースとし、CSS 変数・TS 型・Tailwind アダプタを生成する。
**値は規則から導き、既存プロジェクトから抽出しない。**

## 導入の深さは3段階ある

| 深度 | 内容 |
|---|---|
| `@sashigane/tokens` | CSS 変数のみ。React 非依存 |
| `@sashigane/<component>` | コンポーネント単体 |
| `@sashigane/base` | 全部 |

**トークンのみのインストールが実際に動くことが、層分離の証明になる。**

## コンポーネントは順に足している

いまあるのは **Card と Button の2つ**で、続きは Badge → Separator → Table と決めてある。
**「あった方が良さそう」では追加しない。**

## AI が読む形も配っています

人が読む URL の**末尾に `.md` を足すだけ**で、同じページが素の Markdown で返ります。

```
/docs/components/badge      人が読む
/docs/components/badge.md   AI が読む
```

一覧は `/llms.txt`、全文をまとめたものは `/llms-full.txt` にあります。

**展示は例のソースに展開されます。** このサイトは「どう書くか」を例に預けているので、
差し込みのタグだけが残ると**書き方が1つも伝わりません。**
## どのコンポーネントも自分の名前を名乗ります

すべての部品が `data-sg-component` で自分の名前を出します。**見た目は持ちません。**

```html
<button data-sg-component="button" class="…">
<div data-sg-component="card" data-sg-surface="surface" class="…">
  <div data-sg-component="card-header" class="…">
```

CSS でもテストでも、**組み立てたクラスに頼らずに部品を狙えます。**

```css
[data-sg-component="card"] { /* … */ }
```

`asChild` で要素を差し替えても**名乗りは子へ移ります**——器が変わっても、
何であるかは変わりません。

**クラス名にしていません。** クラスにすると、このリポジトリの検査が
「素の Tailwind にも我々にも無い名前」として**見逃す範囲**に入り、
打ち間違えても永久に気づけません。data 属性なら、
**名乗っていることと、名前がずれていないことを機械で見られます。**

## 設計の記録

このリポジトリは AI 駆動開発の実践例を兼ねている。
**設計判断の根拠と、失敗の記録が成果物の一部である。**
決定の全文・退けた案・改訂履歴はリポジトリの `docs/` にある。
